# 見せる頁と話すメモを分け、現在と次の頁を見ながら発表できる資料にする。

暗色と明色を交互に置き、行程と計画値を原典の版式へ配置。発表者画面は次頁の枠を拡大し、全7頁の目的・講稿・次へのつなぎまで確認できるようにした。

## 入力と出力

入力：伝える主張、受け手、原稿と図の素材、頁ごとの目的・話す要点・次へのつなぎ。

出力：Magazine風のHTML7頁と、現在/次頁・講稿を持つ原典発表者画面。

## 自分の資料へ使う

1. Magazine/Swissと読者・素材を決め、該当する原典テンプレートを実際にコピーする。更新確認を行い、固定取得物を使う場合はその判断を残す。
2. 各頁のlight/dark/heroを先に並べ、3頁以上同じテーマを続けない。原典の登録版式から主張に合うものを選ぶ。
3. 頁IDごとにタイトル・目的・話す要点・次へのつなぎを書き、SPEAKER_NOTESと対応させる。
4. 原典validatorを実行し、P表示の現在/次頁・講稿・戻る/進むを全頁で操作する。観客画面の同期は別の画面を見て確認する。

## 実際に使った機能

- 原典Style A templateを使用し、頁IDと7件の固有講稿を一対一に結ぶ。
- 原典Pボタン→次へ6回を操作し、現在/次頁と全7講稿を1920×1440で保存。全メモがスクロールなしで収まる。
- 3頁はPipelineの順序を6停留所へ横展開した派生。5頁は原典Layout3の計画値表示。暗→明のテーマ間隔を保つ。
- 原文validatorの中国語ラベル不一致3件を保持し、日本語期待値だけの差分では0件。固定1280×720 iframeを等比縮小し、次頁にも十分な高さを配る局所CSS差分。

## 未実施と条件

- Swiss、画像グリッド、スクリーンショット整形、WebGL背景の動き、Step0の上流更新確認は今回未実証。
- 独立した観客画面を人が見て同期確認した範囲は未達。同期済みUI表示、現在/次iframeの確認とは区別する。レーザー/囲む・黒白幕・freeze・リハーサル・自動送りも未実証。
- 発表者画面の画像は制作側の実ブラウザー操作。直接file表示とHTTP表示の双方を同一条件で比較していない。サイト内作例とQAは同一originのHTTPで配信。
- 原典一般ルールの全段階達成を宣言しない。大きな表や長文研修、複数人編集には別方式が適する。

現在の再現コマンドはREPRODUCE.md、原典の条件と日本語での一般手順はSKILL.md、現在の実行・画像hashはQA.json。初回PROMPTの限定検査指示は過去の依頼で、後続修復の範囲はこの記録とsourceのRound4ログを使う。
