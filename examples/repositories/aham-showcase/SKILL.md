# 対話で構成と版式を決める

この作例は版式選択と変換の実演で、8段階対話の実演ではありません。原典の全体は、読み手と目的、材料、主張、標題列、版式、見本、ページ設計、品質確認を8段階で進める手順です。各段階の確認で、話の内容が決まる前に装飾だけを作ることを防ぎます。

## 原典の手順

| 段階 | 決めること・成果 |
|---|---|
| 1 | 読み手・目的・期待行動、発表条件、テーマ |
| 2 | 元資料の事実・数値・出典、欠落と矛盾 |
| 3 | 受け手に伝える主張 |
| 4 | 標題列と証拠の対応 |
| 5 | 頁別の内容・推奨版式・代替2案・配置 |
| 6 | 表紙・複雑な内容・図表の見本確認 |
| 7 | 計画どおりのSVG、3頁ごとの確認、PPTX変換 |
| 8 | 五層QCと内容/視覚監査、配布物 |

各段階で対応するphase文書を読み、原典の確認点を守る。経験者向けの確認統合例外を、無制限な段階省略と混同しない。原典ではcoach-engineも使う。

原典の標題は主語を特定できる結論文、24字以内、数字なし、読点1つまで。版式はlayout-libraryの決定表から選び、D類データ3件以上は図表化する。SVGが原稿で、PPTXを直接直さずSVGへ戻る。画像としてのSVG/HTMLスライドは原典が別のppt-svgへ振り分ける。

## この作例の実施範囲

版式選択と変換の実演で、8段階対話の実演ではない。頁ごとの内容から、時間配分をGantt、前後関係を流れ図、並行する試行を泳道図へ当て、同じSVGから編集可能PPTXへ変換する。

- 2頁・時間配分：3・10・5・2分の棒と0〜20の軸を照合する。青は10分だけ。下の合計20分と例示値の注記を確認する。
- 3頁・前後関係：前日→朝→終了時の矢印と、各箱の下の具体的行動を読む。箱と矢印の相対配置を保ち、全体を中央へ移した。
- 4頁・並行する計画：取り組み・記録・相談の横の3泳道と0〜4週を照合。破線枠はすべて凡例の「提案」で、実施確定の実績へ変えていない。

## 再生成

```powershell
python generate.py --sample
# 見本を描画・確認し、phase-06-decision.jsonへ判断の主体を区別して記録
python generate.py --final
```

P5計画の判断がなく、P6見本のdecisionがapproveでない場合は止まる。現在は自律改修の委任を受けた担当の判断で、人間確認済みではない。原典lintは変換の前後に実行し、終了コード0だけでなく[!]/警告行を確認する。生成先source/final/deck.pptxと配布用deck.pptxは同じbytes。現在の実行順序はsource/round5-execution.json、配布再実行はsource/zip-replay.json。

## 制約と差分

- この作例は版式選択と変換の部分実行。8段階のユーザー対話・coach-engine・P7の3頁ごとの確認・P8の全五層QCを完走していない。
- 現在のP5計画判断とP6見本判断は、自律改修の委任を受けた担当の判断。過去のユーザー承認として扱わない。
- Aテーマの白地・中性グレー・青を使用。初回依頼のコバルト・黄・墨は現版に使わない。
- 原典関数と変換器は固定保存。書体/和訳に加え、P2/P4ラベルのサイズ・濃度、P3の平行移動・補足、終端20・日本語凡例を局所補正する。原典そのままの字号・座標とは記載しない。
- 数値と期間は架空ワークショップの例示計画。仕事の改善・健康・時間短縮の実績ではない。
- 公式Zen Kaku Gothic New/Manropeを同梱し、実PDFでも使用を確認。PPTXへ埋め込まない。
- SVG/HTMLの画像スライドが目的なら原典は別のppt-svgへ振り分ける。ここで実証するのは編集可能なPPTXの経路。
- 原典lintは終了コード0だけで合格とせず、出力の警告/違反行も確認。独立再評価と利用者採用は別。
