# Quality Audit Protocol · 质量审计协议

> 可插拔模块。独立升级不影响其他Phase。
> 适用阶段：Phase 7（逐页设计）→ Phase 8（质检与交付）。
> 目标：在调用 svg_to_pptx 转换之前，通过自动化检测拦截已知问题；
> 在交付之前，通过标准化审计流程确保输出质量。

---

## 一、三级关卡机制（Three-Gate System）

每页SVG生成后、调用转换工具前，工具链自动执行三级检查。
检查结果以 WARNING 形式输出到转换日志，**不阻断转换流程**
（因为部分WARNING是风格问题，由人工决定是否修改）。

| 关卡 | 检查对象 | 工具链行为 | 需要人工干预的情况 |
|:---:|:---|:---|:---|
| Gate 1 | 逻辑完整性 | 检测空的 `<text>` 元素（占位符未填充） | WARNING出现时，回到Phase 7修复内容 |
| Gate 2 | 版面合规性 | 检测超长行（保守阈值，非阻断警示）；**权威字数上限见 `grid-system.md §八`**（按容器宽度×字号查） | WARNING出现时，对照 grid-system §八 判断是否真超宽，超出则拆分文字 |
| Gate 3 | 代码合法性 | 自动修复裸露`&`；检测rgb()/hsl()颜色格式 | rgb()/hsl() WARNING出现时，改为品牌规范hex色值 |

**颜色政策（硬性底线）：** 所有颜色决策以 `brand.md` 品牌规范为唯一来源。
工具链不做颜色白名单校验，但会对 `rgb()/hsl()` 格式发出 WARNING，
因为转换器只支持 hex 格式，遇到 `rgb()` 会静默 fallback 到黑色。

## 二、转换前自动执行项（工具链内置，无需手动触发）

以下检查在 `svg_to_pptx_wrapper.py` 调用时自动执行：

```
每个SVG文件转换时：
1. [Gate 3] 自动修复裸露 & → &amp;
2. [Gate 3] 扫描 rgb()/hsl() 颜色格式，输出 WARNING
3. [Gate 2] 统计每行CJK字数，超过20字输出 WARNING
4. [Gate 1] 检测空 <text> 元素，输出 WARNING
5. [tspan] 自动将 <tspan dy=...> 拆成独立 TextBox（无需人工处理）
```

## 三、交付前人工审计流程

### 步骤1：HTML预览审查（强制）

所有SVG转换为PPTX之前，先生成 `preview.html` 预览文件。
在浏览器中逐页检查：

```
审查清单 · 通用：
□ 文字是否有溢出（超出卡片或页面边界）
□ 文字是否有重叠（两个TextBox坐标重合）
□ 箭头是否正确显示（用polygon画的箭头应完整）
□ 多行文字是否正确换行（不能挤在一行）
□ 转换日志中是否有 WARNING（对照警告逐项检查）
```

**视觉合规审计清单（Aham UI v6.1 · 逐项勾选）**

> 本清单是视觉合规的**唯一详单**（phase-08 L2 不复写）；机判项（色值精确比对/图文重叠/字体扫描）以 phase-08 L2 为准。
> 由 phase-08 步骤1 显式调用执行。

权威取值见 `brand-spec/tokens.css`：

```
□ 无顶部蓝条；蓝只出现在点缀位（logo点 / 主操作 / 选中下划线 / 推荐标 /
  单个高亮数据点 / 封面短线），全页蓝面积极小
□ 无衬线字体（标题 / 正文均无衬线，数字用 mono）
□ 卡片无边框无阴影；分块靠留白 + #E7E7E7 细横线；选中=扁平灰非蓝
□ 表格只横线、无竖线、无整行底色；数字右对齐 mono；表头 / 合计加粗
□ 状态=6px 点 + 文字，无 pill / 徽章 / 红黄绿灯
□ 图表灰阶(#9B9B9B / #C8C8C8) + 至多一个 #336EE8 高亮，面型数据元素带 1px #6E6E6E 描边；坐标轴 #E7E7E7；
  无 3D / 阴影 / 渐变 / 饼图
□ 颜色只用规范白名单（三层灰 #FFFFFF / #F3F3F3 / #E7E7E7 +
  墨 #262626 / #6E6E6E / #9B9B9B / #C4C4C4 + 图表次色 #C8C8C8 + 蓝 #336EE8 系 +
  语义 #5A7A60 / #8A7333 / #9E3D31 + 登记装饰专用 #2E2E2E(章节水印)/#333333(金句引号)/#F7F8FA(占位框底)）；无纯黑 #000、无第二装饰彩色
□ C 档深色重音页（封面/章节/金句）专用 ramp（仅这三类页）：底 #1C1C1C，
  信息文字 #F2F2F2 / #A8A8A8（#787878 仅装饰性弱字，不承载须读取信息），线 #3A3A3A，块 #262626，
  蓝点缀 #336EE8（装饰）；深底信息性蓝字用 #5C8BED（见 tokens.css §10）
```

**视觉合规审计 · v3 防平淡组（正向，与上面的“防过度”对称）**

```
□ 每页有视觉主体（数据图表 / 结构图 / 大数字 / UI原型 / 关系图 之一）；纯文字卡须在规划卡写明理由
□ 数据页用了 charts 组件，多条 D 类数据未被文字化
□ 图形版式占比达标：连续纯文字版式 ≤2 页；数据图表页 ≥ ⌈内容页/6⌉
□ 节奏有起伏：每章 ≥1 个重音页（深色章节/金句 或 半幅大数字 I 系）；无连续 ≥3 页同密度同色调
```

### 步骤2：PPTX抽样检查

转换完成后打开PPTX，抽取3页检查（选最复杂的图表页）：

```
检查项：
□ 文字是否可编辑（双击文字框应进入编辑状态）
□ 形状是否可独立选中（单击形状应选中单个元素）
□ 图片是否变形（图片宽高比应与SVG一致）
□ 中文=微软雅黑、数字=Consolas（PPTX 落地）/ JetBrains Mono（SVG 源）、无衬线（无乱码）
```

## 四、AI生成SVG时的强制约束（Prompt附加段）

在执行逐页设计任务时，以下约束自动附加，无需重复提示：

```
[质量管控约束 · 自动执行]
1. 特殊字符：文字内容中的 & 写为 &amp;，< 写为 &lt;，> 写为 &gt;
2. 颜色格式：所有颜色使用 hex 格式（如 #336EE8），禁止 rgb() 或 hsl()
             颜色必须来自品牌规范（brand.md / tokens.css 白名单），这是硬性底线
3. 换行方式：多行文字用 <tspan x="..." dy="1.4em"> 或独立 <text y="...">
             禁止在文字内容中使用 \n
4. 箭头画法：禁止 <marker>，必须用 <polygon> 绘制箭头头部
5. 绝对坐标：禁止 <g transform="rotate(...)">，使用绝对坐标
6. 单行长度：单行字数上限以 grid-system §八 为准（按容器宽度×字号查，如 1200px 容器 14px 约 43 字）；超出必须换行
```

## 五、常见问题快速定位

| 现象 | 最可能原因 | 快速修复 |
|---|---|---|
| 整页空白 | SVG含未转义`&` 或XML结构损坏 | 检查转换日志的ParseError；工具链已自动修复`&` |
| 箭头消失 | 用了`<marker>`在`<path>`上 | 改用`<polygon>`画箭头 |
| 多行文字变一行 | 用了`\n`换行 | 改用`<tspan dy>`或独立`<text>` |
| 颜色变黑 | 用了`rgb()`格式颜色 | 改为hex格式，查brand.md对应色值 |
| 文字位置偏移 | `<g transform="rotate">`坐标偏移 | 用元素级绝对坐标替代 |
| 文字溢出容器 | 单行字数过多 | 换行，或按字数参考表缩减内容 |
| 文字无法编辑 | 非native模式转换 | 确认通过`svg_to_pptx_wrapper.py`调用 |


## 自动预检 + 双轨审计

**渲染前/后自动预检（`assets/tools/lint_svg.py`）：** ①tofu 高危字符 ②页脚总页数一致 ③源码中文双引号。

**交付前双轨人审：**
- 内容审计（对《项目基线》逐页核：架构/主线/场景/数字，标冲突与出入）；
- 视觉审计（排版对齐/单一强调色/前后矛盾/错别字/重复啰嗦/自造概念词）。
- 产出结构化报告 → 用户批准 → 再改。
