# 变更与恢复

仅在用户修改需求、交付后修改或恢复到不同版本时读取。状态与授权门禁以 `SKILL.md` 为准。

## 先记录变更，再修改产物

在 `deck-spec.md` 记录用户原话、修改范围、受影响页/元素 ID、修改前后值、内容与风格版本、回退状态和失效产物。明确指定的修改已获该范围授权；未指定的内容、重新选风格等仍需按门禁判断。

首次更改已验收页面前，把当前 Page Spec 保存为 `snapshots/page-spec-<旧版本>.json`，保留原基准图片。为每页记录基准图片路径、SHA-256、内容版本和风格版本；同一路径被替换后必须重新核对，不能沿用旧验收。

可用下列命令同时保存批准图片、风格参考图和语义内容的哈希；修改 Page Spec 后生成只读影响计划：

```sh
python "<skill-dir>/scripts/plan_deck_update.py" snapshot "<work>/page-spec.json" "<work>/snapshots/baseline.json"
python "<skill-dir>/scripts/plan_deck_update.py" plan "<work>/snapshots/baseline.json" "<work>/page-spec.json" "<work>/update-plan.json"
```

计划把页面分为 `reuse`、`review_existing`、`regenerate`。全局风格或风格参考图像素变化会影响所有页；追加或删除末页可复用其余未变页面，但仍须重建导出文件。页码/页序、单页内容变化只影响对应页。对包含总页数或依赖整套页数构图的页面，在 Page Spec 设置 `depends_on_slide_count: true`，页数变化时重做这些页。未设置该字段的旧任务默认不依赖总页数；规划前核对旧页面并补齐依赖标记及实际可见文字，避免遗漏 `1/10` 等内容。`stale_approval: true` 表示语义已变而 Page Spec 仍写 `approved`，必须按实际交付范围修正状态并重新验收。计划不修改用户授权、Page Spec 或图片；可编辑版局部修改仍按下文保留历史基准。

## 变更影响表

| 变更 | 状态与确认 | 需要更新或失效的产物 |
|---|---|---|
| S1/S2 中修改大纲 | 回 S1 更新逐页内容稿并复核受影响自检项，再展示；具体修改已授权，未决定项在自检通过后留在 S2 | 更新 `deck-spec.md` 内容版本、自检和授权记录；Page Spec 尚不存在时不创建 |
| 制作期间修改文字、数据或结论 | 明确修改且原风格仍适用时回 S5；需要 Agent 决定的新内容先回 S1/S2 | 提升内容版本，更新已有 Page Spec；受影响图片设为 `revision`，对应 Scene、渲染和导出失效 |
| 修改配色、字体、布局系统或页面比例 | 回 S3，按风格门禁判断锁定参考、豁免或重新选型 | 更新风格版本及必要的 canvas；受影响图片、Scene 坐标、渲染和导出失效。全局视觉变更影响全部页 |
| 增删或重排页面 | 用户给定的新顺序直接采用；新增内容未确定时先回 S1/S2，否则 S5 | 保留既有 slide/element ID，重编 `page_number`；新页及页码/总页数等可见内容变化的页面设为 `revision`，重做相关图片与导出 |
| 已有 Scene 的可编辑版局部修改 | 保持或恢复 S6，具体修改无需再次确认 | 同步当前 Page Spec、Scene 或素材；重新编译、审查和渲染。受影响旧图片设为 `revision`，仅保留作历史基准 |
| 只改变交付范围 | 按已有授权继续 S5/S6 或结束 | 无内容/视觉变更时保留已验收页面，不重复确认已完成阶段 |
| 只修改可选讲稿 `speaker_notes` | 同步内容稿中的明确修改及 Page Spec/Scene 讲稿；可见内容未变时保留图片验收 | 计划返回图片 `reuse` 和 `export_reasons: [speaker_notes_changed]`；重建 PPTX、独立讲稿及备注核对，旧评分卡失效；不重复生图 |

S5 失效页面重新验收后才能恢复 `approved`。若内容或风格确认被撤回，在 `deck-spec.md` 记录待确认状态，停止相应阶段；不要把未经确认的内容写成 `content_approved: true`。已交付版本保留版本标识，不再作为当前版本交付。

改变正文、数据、结论或页序时，同步当前内容稿并按 `references/content-outline.md` 复核受影响的论证、口径和衔接；不重复审查未变页面，不为已明确授权的修改重复等待确认。排版空间不足不能成为删掉已确认解释或必要边界的理由，应记录并处理内容变更。

修改表格或图表数据时，一并定位依赖它的差值、占比、排序、结论和 `speaker_notes`；按明确来源与计算更新，无法确定的关联项先标记待核验。数据对象可编辑不代表其他文本会自动联动。重编后核对实际嵌入工作簿与可见数值，并查看修改页的关联说明；演练也须区分合成数据与正式事实，不能仅凭单元格已改变就判整页修改成功。

声明数值依赖时读取 [data-bindings.md](data-bindings.md)，用可选契约同步 Page Spec/Scene 的数据、衍生计算、正文和讲稿。先预览前后差异，再导出独立待审草稿；未声明的依赖仍需核对，原验收不能沿用。

## 可编辑版修改与历史图片

修改原生文字、几何或数据不需要重新生图。当前 Page Spec 记录最新获授权内容，基准快照保留旧图片对应的内容。变更表记录二者的精确差异，例如：

| 基准版本 | 当前版本 | 页 / 元素 | 已授权变化 | 图片状态 | 交付范围 |
|---|---|---|---|---|---|
| outline-v1 / style-v1 | outline-v2 / style-v1 | s03 / revenue | 12 万 → 15 万；用户原话与时间 | revision（历史基准） | 仅更新可编辑版 |

已记录且与授权一致的差异不是待确认冲突。恢复 S6 时使用当前内容与历史视觉布局，只对新增、未记录或超出授权的差异请求确认。Scene 的 `source_image` 继续引用原始基准图供检查，不改指向当前 PPTX 的渲染图。

若用户同时要求最新图片版，从修改后的可编辑 PPTX 渲染受影响页并检查，更新 `image_file`、`image_status` 和验收记录，再按 Page Spec 合并。尚无可用渲染结果时不得把旧图片重新标为 `approved`；只交付已完成范围并说明图片版待更新。`--require-images` 用于交付当前图片版，不用于阻止有明确历史基准的可编辑版局部修改。

## 恢复顺序

1. 读取当前状态、用户授权、版本记录和未完成变更。
2. 对照 Page Spec、Scene、基准图路径及哈希确认版本归属；只有存在且匹配记录的产物可复用。
3. 按变更表定位最早需要重做的阶段和页面；保持其他稳定 ID 与有效产物。
4. 完成相应验证与渲染后更新验收记录，再记录 DONE 和本次实际交付版本。
