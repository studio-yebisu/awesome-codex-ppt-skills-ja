# Carousel Brief — 引き継ぎ、何を書けばいい？

## 概要

| 項目 | 内容 |
|---|---|
| 目的 | 初めて引き継ぎメモを書く人へ、記入の入口を示す教育用カルーセル |
| 用途 | SNSカルーセルの構成確認 |
| 枚数・寸法 | 6枚 / 1080×1080 |
| 読み手の段階 | TOFU / 初めて知る人への説明 |
| 語り口 | 短く、親しみのある実務向け |
| 納期 | 今回のローカル試作 |
| 修正回数・承認者 | 公開用制作へ進む際に依頼者が決定。現在は人による承認待ち |

ブランドはinput/brand-guideline.md、読み手はinput/product-marketing-context-global.mdを参照。

## 流れ

Hook → Problem → Insight → Solution → Example → CTA。実績の証拠がないためProofを捏造せず、架空の記入例へ変更。

## Brand direction

色・字体・自作しおりマークはinput/brand-guideline.mdを参照。CTAボタンは「記入型をコピー」。Logoは各頁のしおり図形、contactは未設定で架空の連絡先は作らない。公開用デザイン・連絡先・人の承認は別工程。

## Slide 1 — HOOK

| 要素 | 内容 |
|---|---|
| 見出し | 引き継ぎ、 / 何を書けばいい？ |
| 本文 | 詳しく書く前に、 / 次の人が動ける3点を。 |
| 図案 | 3本の記入線を持つメモのベクトル図 |
| 背景 | 濃緑 / 白系の文字 |

## Slide 2 — PROBLEM

| 要素 | 内容 |
|---|---|
| 見出し | 「よろしく」だけでは、 / 次の一手が見えない。 |
| 本文 | 終わったことと、残ること。 / 読む人には、どちらも必要。 |
| 図案 | 一言のメモと空欄の次の作業を対比 |
| 背景 | 生成り / 濃緑の文字、銅色のアクセント |

## Slide 3 — INSIGHT

| 要素 | 内容 |
|---|---|
| 見出し | 書くのは、 / 目的・次の一手・相談先。 |
| 本文 | 全部の経緯より、 / 迷ったときの入口を残す。 |
| 図案 | 3点を番号付きの縦カードにする |
| 背景 | 生成り / 濃緑の文字、銅色のアクセント |

## Slide 4 — SOLUTION

| 要素 | 内容 |
|---|---|
| 見出し | 今日の作業を、 / 3行のメモにする。 |
| 本文 | 目的は何か。次に何をするか。 / 迷ったら誰に聞くか。 |
| 図案 | 各項目に短い質問を置く記入フォーム |
| 背景 | 生成り / 濃緑の文字、銅色のアクセント |

## Slide 5 — EXAMPLE

| 要素 | 内容 |
|---|---|
| 見出し | たとえば、 / 資料の確認を頼むなら。 |
| 本文 | 読む人が、次に動けるか。 / 記入例で確かめる。 |
| 図案 | 架空の資料確認メモを3項目で示す |
| 背景 | 生成り / 濃緑の文字、銅色のアクセント |

## Slide 6 — CTA

| 要素 | 内容 |
|---|---|
| 見出し | まず1件、 / メモを書いてみよう。 |
| 本文 | 目的・次の一手・相談先。 / この型から始める。 |
| 図案 | 記入型をコピーする実ボタンとメモのベクトル図 |
| 背景 | 濃緑 / 白系の文字 |

## 引き渡すもの

- このブリーフと編集できるHTML、入力JSON。
- HTMLとPNG6枚は構成確認用。SNS公開用の制作データではない。
- コピー確認 → HTML構成確認 → Canva/Figma/Adobe Express等で仕上げ → 人による確認 → 公開、という原典の段階を区別する。今回の例はHTML構成確認まで。
- LinkedIn用の公開PDF、縦長版、人の承認、投稿は今回の対象外。
