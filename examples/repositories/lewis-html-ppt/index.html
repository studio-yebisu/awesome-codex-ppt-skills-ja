変更を届けるまで

小さな変更を、順番に届ける

01今の変更を見る
02記録する変更を選ぶ
03変更の理由を残す
04共有してレビューする
05最初の一歩を試す
一覧を丸暗記せず、変更がどこにあるかを意識して順に進めます。

保存・記録・共有

保存・記録・共有は別の操作

ファイルの保存

エディターで保存した変更は、作業フォルダにあります。

履歴への記録

commitで、選んだ変更を履歴に残します。

チームへの共有

pushで、リモートへ変更履歴を送ります。

保存はcommitでもpushでもありません。この違いを最初に押さえます。

今の変更を見る

まず今の変更を確かめる

git status は変更の場所を、git diff は変更の中身を示します。まず対象のファイルを確認します。

作業フォルダ 差分 対象の確認
変更の確認
$ git status
modified: README.md

$ git diff
説明文に、新しい手順を追加
statusで位置、diffで中身を確かめます。

記録する変更を選ぶ

記録する変更を選ぶ

今回届けたいファイルを git add で選び、git diff --staged で記録する差分を読みます。

1. README.mdの変更を読む
2. git add README.md
3. git diff --staged

記録の前に見ること

依頼された変更か

不要なファイルが混ざっていないか

何を変えたか説明できるか

addで選んだ変更が、次のcommitの対象になります。

履歴に残す

変更を説明して、記録する

履歴への記録
$ git diff --staged

$ git commit -m "説明書にセットアップ手順を追加"

$ git log -1 --oneline
変更の記録と、理由を確認
変更を残す前に差分をもう一度読みます。

チームへ届ける

チームへ共有し、レビューする

ブランチ

チームが決めた作業ブランチで変更する。

push

送り先とブランチを確認して、履歴を共有する。

レビュー

変更の目的・内容・確認方法を説明する。

参照：git-scm.com/docs / GitHub公式ドキュメント

レビューの目的は、変更をチームが理解して確認できることです。
