# 日本語の企画・導入提案

企画を理解して判断できる資料にする。読み込む元テンプレートと参照は選んだ方式に絞る。

## 方式と入力

- Magazine：体験や地域の企画向け。対象者、体験、行程、運営、予算、検証、次の判断を渡す。例：「架空の港町で、案内所→市場→食堂→工房→灯台→案内所を徒歩で回る半日企画。2週末4日の試行。参加店舗の合意後に日程を決める。7枚。」
- Swiss：構成・比較・段階導入の提案向け。課題、利用場面、構成、方式比較、担当、評価、判断を渡す。例：「50人の架空組織で30資料を台帳化し全文検索を4週間試す。30問中24問以上で正しい資料へ到達、権限外資料は20ケース中0件。回答生成と全社展開は評価後に別判断。8枚。」

予算6＋16＋6＝28万円のように内訳から集計。目標60人を参加実績として書かない。図の矢印は処理・移動・責任のどれを表すか決める。架空例にはその旨を成果物にも残す。

## 日本語化

assets/template.htmlまたはassets/template-swiss.htmlへ内容を挿入。SwissのS01–S22登録版式を保持し、ページの役割に合うものを選ぶ。日本語用にlang、字形、行間、意味での改行、必要な枠を調整する。元のテーマ・英字の性格・ページ制御・Motionを共通機構へ置換しない。

Magazineの短い見出しにはNoto Serif JP、本文・図表にはNoto Sans JPなど役割を分ける。Swissは情報階層を優先。「社内ナレッジ検索／4週間で判断する」のように意味で分け、長い日本語を短い英語と同じ枠へ押し込まない。中国語書体へのフォールバックを避け、権限・資料・全角括弧なども実表示で確認。詳細は[japanese-fonts.md](japanese-fonts.md)。

禁則と明示改行を組み合わせ、行頭句読点・閉じ括弧、数字と単位の分断を確認。比率を保ってステージを縮小し、狭い画面で本文の構図を変えない。脚注を縮めて詰めず、講稿・補足へ分ける。

## 講稿・QA・配布

ページIDと講稿を一対一にする。話す順序、仮定、求める判断を書く。時間指定は目安であり、実際の読み上げ時間を保証しない。

スキルrootから、DECK/index.htmlを制作物パスへ置換して実行。Nodeとブラウザ依存は上流手順で準備する。

```sh
node scripts/validate-presenter-mode.mjs DECK/index.html --target-minutes 8
```

Swissだけ追加：

```sh
node scripts/validate-swiss-deck.mjs DECK/index.html
```

合格結果と別に、全ページ・操作・字形・発表者表示・講稿対応・動きと静止時の可読性をブラウザ確認する。未実行の結果を先取りしない。印刷や書き出しを提供する場合はその出力を別途開く。

CDN依存ならオンライン条件を示す。オフライン版は必要依存と書体を相対パスで同梱して実行確認する。テンプレート派生コードのAGPL、MotionのMIT、LucideのISC、各書体の条件を保持し、改変ソースを取得できるようにする。

カタログ全体ではdata/case-inputs.jsonのharbor/knowledgeが正本、examples/cases/port-town/とexamples/cases/knowledge-search/が対象。状態は各制作記録とdata/case-studies.jsonで確認。この題材は初回例であり、新規資料をこの内容に固定しない。


カタログの日本語UIでは、原典のページ制御を保ちつつ計時などの操作ラベルを日本語化。日本語表示のvalidatorは、開始・再開・リセットの作用名が明示されているかを元の検査と同じ条件で確認します。動きを減らす設定では、ページ移動のアニメーションと待機lockを無効にして、操作と表示ページが一致するようにします。
