# 現行方針：掲載GitHubリポを実際に使った日本語スライドガイド

製品仕様の正本は [PRODUCT_SPEC.md](PRODUCT_SPEC.md)。最新のユーザー訂正「取り上げた多くのGitHubリポを実際にこの環境で使い、スライドを作って、そのリポでこんな資料が作れるという案内にする」を優先する。

## 主語と作業対象

主語は掲載リポジトリ。元209件・6分類を起点に、多くのリポをそれぞれの固有方式で実行し、日本語の生成例、使った環境、具体的な実行方法、入力・成果物、原典・条件をリポ単位で結び付ける。

作品の題材や枚数を増やすことは、実行したリポの種類を増やすことの代わりにならない。**3リポ・6冊・45枚は製品の完了条件ではない。** 既存6冊は3リポの利用を示す部分成果として保全し、他の掲載リポの実行・生成・利用案内を進める。

## 正本とデータ

- data/skills.json：元209件。全フィールド、作者、順序、分類を保持する。
- data/repository-audit.json：原典の取得・読取の棚卸し。全件を機械確認しても、個別条件のレビュー・制作実行・採用が完了したとは数えない。根LICENSEと一部実装の条件差やarchived状態を確認する。
- data/project-workflows.json等のリポ単位台帳：原典、状態、環境、実行方法、実行記録、作例、派生、阻害条件。
- data/case-studies.json：日本語生成例。repositoryと実行記録に結び付ける。6件固定にしない。
- data/case-inputs.json、examples/cases/等：既存入力・制作ソース・成果物・検証。新リポの入力形式に応じて拡張可能。
- skill-forks/：条件を確認して日本語向けに改良した派生。取得・翻訳・包装だけで生成成功と数えない。

掲載、調査、実行試行、生成成功、表示確認、未着手、阻害条件を区別する。同じリポの複数作品を別の実行リポとして数えない。作品数・ページ数は補助的な件数である。

## 実行と利用案内

CLI、MCP、指示型SKILL、固有テンプレート、変換、外部API等の実際の入口を原典から確認する。各リポの方法で生成し、コマンドまたは依頼と操作、入力、環境、結果を残す。共通自作rendererで作った資料にリポ名だけ付けることは禁止。

リポ詳細から、そのリポの日本語作例をフロートで全ページ閲覧でき、成果物、入力、依頼文、具体的な使い方、原典へ辿れる。サイトの主画面を少数の業務テーマ集へ置換しない。

必要な依存の準備や可逆的な修正は進める。動かせないものは具体的なエラー・不足条件・再開条件を記録し、未制作と示す。未着手を試行済みと偽らず、実行可能な別リポの制作を続ける。

## 既存案との関係

- 独立5スキル・共通rendererの6デッキへの置換：不採用試作。
- 自己紹介題材3冊12枚：不採用試作の記録。
- 3リポの業務題材6冊45枚：使える部分成果。ただしこれを初回製品の完了条件とした旧仕様は撤回。

data/actual-examples.json、examples/actual/等の旧記録は保全するが、現行件数へ自動算入しない。既存のnativePPTX、PowerPoint描画、Web再生、書体、包装・検証部品は利用できる。

## 品質・条件・完了の報告

PPTX入力SVGの表示とPowerPoint本体による描画を区別する。HTMLの表示・操作・編集・印刷も実施範囲を記録する。検証成功を人の採用や美術品質の保証にしない。

原作者、固定commit、上流ファイル、改変点、MIT／AGPL等の条件、素材・フォントの条件を保持する。一覧のCC0を掲載コードへ一括適用しない。

リポごとの実行実績と未実施範囲を中心に報告する。作業バッチの完了と依頼全体の目的達成は分ける。少数リポの作例数だけを達成して作業を閉じない。詳細な受入条件は [PRODUCT_SPEC.md](PRODUCT_SPEC.md) に従う。

外部公開、正式採用、main mergeはローカル実装・技術QAと別。既存の公開URLとリポ名を維持し、公開更新等はユーザー指示に従う。
