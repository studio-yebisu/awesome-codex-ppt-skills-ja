## 目標

Studio Yebisu独自のAIスライドサイトとして、原典GitHubスキルを実際に使った魅力的な日本語資料を増やす。完成スライドをすぐ再生し、気に入った作風の日本語スキル本文を直接取得し、OSSフォントと依頼文を使って自分の題材で制作できる状態にする。

209件は出発点の資料。全件の制作・阻害条件調査・掲載維持を義務にしない。現行の厳選集は `data/product-collection.json`。原カタログ、既存制作物、原作者と条件は保存する。

## 制作方針

- 今後の既定モデルはClaude Opus 5.5。2026-10-14までの掲載作例はSol 6.1中心の並列制作の実績として、その表記を保つ。Astraは使わない。
- 親は方針、サイト、フォント、ダウンロード、統合。子は作例・入力・短い使い方を完成させる。
- 原典SKILL、固有テンプレート、controller、生成器を適用。日本語の書体・改行・コピー・図形・演出を改良し、改変を記す。
- 大胆な文字、図形、誌面の余白、図解、短い動きを使う。同じ淡色の業務テンプレートへ揃えない。
- OSS書体を原配布物と条件付きで揃え、見出し・本文・英数字・コードの役割をAIへ渡せるようにする。等幅のコード書体と日本語本文のフォールバックも指定する。

## 必要な確認だけ

生成成功と主な完成ファイルの初回表示を確認し、明白な欠けやリンク切れを直す。原典ビルドに含まれる確認は実行する。全ページ詳細目視、独立採点、構造監査、完全ZIP再実行を必須にしない。問題がなければ再検査しない。

生成と確認は分けて記録する。過去の大規模QAは履歴として残し、今後の要件へ広げない。

## 目指す完成状態と制作バッチ

1. 新しい目的・製品仕様・制作方針。
2. 掲載する各リポに、原典方式で制作した日本語資料・入力・使い方を揃える。複数の作風と制作方式をカバーする（既存作例はSol 6.1の並列制作）。
3. 作風と完成スライドから選べる厳選一覧とフロートプレイヤー。
4. 日本語スキル本文の直接取得、必要な一式ZIP、GitHubへの導線。
5. OSS日本語・英数字書体とAI向けのデザイン指示。

原典・素材・書体の条件と帰属を保持する。公開更新・main merge・deployはローカル制作とは別に扱う。

初回の新作2冊は制作バッチの成果であり、プロジェクト全体の完了とは分ける。追加する原典ごとに実際の制作例と利用キットを仕上げ、動かせる有用な方式の制作を続ける。

## 2026-10-15 サイト改訂（Claude Opus 5.5）

作例の制作バッチとは分けて扱う。対象はサイト構成・日本語ガイド・使い方で、作例・スキル本文・制作一式・台帳は作り直さない。

- トップの最初に今回の改訂を短く示し、正本JSONから集計した実数（厳選スキル・冊数・通常ページ・段階演出・OSS書体）を早い位置に置く。通常ページと段階演出は合算しない。
- 「最初の一冊を選ぶ」で、動くWeb・編集できるPowerPoint・図解教材の目的別に実在の作例へ案内する。
- 使い方は、完成作例・スキル本文・制作一式・書体の違いと、短い操作順、Claude Opus 5.5へ渡す依頼文例にまとめる。必須素材をメモで代用できるとは書かない。
- `status.html` に現在の実数、今回の改訂、従来作例の制作モデル、確認範囲、公開反映を分けて示す。Opusによる改訂の表示は、親が作る `data/site-editorial.json` が `verification_status: verified` の場合に限る。公開状況は生成時点の記録として示し、到達確認していない公開を記さない。
- 既存61冊はSol 6.1中心の並列制作による原典方式の実作例で、Opus制作とは書き換えない。モデルの一般性能・価格・提供状況は主張しない。
