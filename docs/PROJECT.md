# スキルの効果を伝えるスライドサイト

2026-10-15のユーザー指示が現行方針。完成スライドを並べるだけでは、スキルを選べない。原典GitHubスキルを使うと何が変わり、その特徴が作例のどこに表れ、どう自分の資料に使えるかを示す。

## 閲覧の順序

1. 改善したいことからスキルを絞る。
2. スキルがすること、必要な入力、受け取るものを読む。
3. 該当ページを開き、原典の指示がどう適用されたか確かめる。
4. 環境と利用条件を確認し、本文・必要な実装・自分の原稿をAIへ渡す。

説明は短い日本語にする。作例の題材や雰囲気を、スキルの機能説明へ混ぜない。原典の能力、この作例で試した範囲、未実施・未合格を分ける。

## 制作と評価

既定モデルはClaude Opus 5.5。使った実行記録がある範囲だけ帰属を表示する。以前のSol 6.1の作例をOpus制作へ書き換えない。親は統合と実操作、子は所有を分けた制作・修復・評価を担当する。

原典のSKILL、テンプレート、生成器、変換器、必須検査を使う。独自変更と互換修正は記録し、検査基準を下げて合格にしない。

Kimi K3とClaude Opus 5.5が独立して、効果の説明35点・作例での活用35点・実スライドと操作30点で評価する。同じ版で両者100/100になるまで指摘を修正し再評価する。未確認を満点扱いしない。詳細は [評価条件](SKILL_EFFECT_REVIEW.md)。AI評価と人間の採用判断は別である。

## フォント

Google Fontsなど公式配布元の原配布物と利用条件を保持する。日本語ゴシック・明朝・手書き調、欧文、コード用を用途から選べるようにし、実見本・個別ZIP・公式サイトへのリンクを用意する。欧文だけの書体を日本語対応と表示しない。

## 正本

`data/product-collection.json` が掲載61スキル、`data/skill-effects.json` が効果と該当ページ、`data/skill-needs.json` が用途分類、`data/case-studies.json` が実作例、`data/repository-guides.json` が環境と条件。`data/oss-font-kit.json` が書体の原配布元・ハッシュ・組み合わせ。

原209件と過去作例は履歴として保持する。現在の掲載対象を減らして採点だけ上げない。公開・main merge・deployはローカル改訂と分ける。
