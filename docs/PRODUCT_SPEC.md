# Studio Yebisu AIスライドサイト

2026-10-15改訂。2026-10-14に旧209件全消化・大量QAの仕様を置き換えた。2026-10-15のユーザー最新指示で、今後の既定モデルをClaude Opus 5.5へ揃え、初めての人の導線と制作の状況ページを加える。

## 製品の価値

GitHubのスライドスキルをこの環境で実際に使い、日本語の美しい完成資料・短い日本語派生スキル・OSSフォント・頼み方の組にして届ける。単なる原文翻訳を越えたStudio Yebisu独自のプロジェクトとする。

原典方式を前提に、美術・構成・書体・日本語コピーを改良する。原典のテンプレート、CLI、controller、生成器を活用し、独自拡張を記す。自作汎用描画に原典名だけ付けない。

## 閲覧体験

トップは完成した日本語資料と作風を中心にする。209件の未制作カードや消化率を主画面に並べない。使わないスキルは現行掲載から外し、出発点の原カタログを別の資料として残す。

日本語ユーザーが「作例を見る→日本語スキルを取得→自分の内容で作る」まで迷わず進めることを導線の基準にする。トップの早い位置に、厳選スキル数・冊数・通常ページ・段階演出・OSS書体数を正本JSONから集計して示す。通常ページと段階演出は合算しない。「最初の一冊を選ぶ」は動くWeb・編集できるPowerPoint・図解教材の三つの目的に絞り、実在の掲載作例のフロートと作り方へつなぐ。同じカードを大量に増やさない。

`status.html` は現在の実数、今回のサイト改訂、従来作例の制作モデル、確認した範囲、公開反映を分けて示す。改訂モデルの表示は親が記録する `data/site-editorial.json` が検証済みのときだけ行い、それ以外は保留と示す。公開状況はページ生成時点の記録として示し、到達確認していない公開を記さない。内部パス・ログ・認証情報を表示しない。393px幅で横溢れしない、キーボード操作とreduced-motionを保つ。外部フォント・CDNを追加しない。

「スライドを見る」でフロートプレイヤーが軽快に開く。ページ送り・再生・閉じるを提供し、Web作例では元runtimeの演出を再生する。PPTXは完成ファイルのプレビューを表示。スマートフォンでも主要操作を使える。

作例は題材・作風・スキル名から検索し、形式・編集対象の絞り込みと合わせて探せる。フロートは元資料の縦横比へ合わせる。場面の中で段階表示する資料は「場面・段階」で案内し、通常の枚数へ混ぜない。元に場面の区分がない共通画面の演出は段階だけで案内する。依頼文も元の場面数・段階数の方法に合わせる。

カードと詳細から、日本語スキル本文、完成資料、必要な一式ZIP、GitHub原典へ進める。短いスキルはMarkdownとして直接取得できる。本文だけに原典コードが同梱されるように見せず、必要な参照の固定URLと一式ZIPを案内する。

完成HTML・PDF・PPTXの取得名は資料の題名に揃える。Windowsで使えない記号と末尾の句点を整え、実際の拡張子を保つ。単独HTMLと複数ファイル一式の取得ボタンを分ける。作風の参考にした自作資料も、作例のフロート内から開ける。

使い方では、完成作例・スキル本文・制作一式・書体の違いを分けて説明し、初心者が実行できる短い操作順とClaude Opus 5.5へ渡す依頼文例を示す。

作例の詳細では、自分の題材・原稿・読み手・希望枚数と書体セットから、選んだスキル向けの依頼文を組み立ててコピーできる。選択した作例の固定原典・固有方式・出力形式を含め、実際に作例を作った依頼文は別に読める。必須の論文・画像・PPTXなどを入力メモで代替できるように見せない。フォームは画面内で動作し、入力を保存・送信しない。

## 日本語と美術

見出しは意味の区切りで改行。見出し・本文・英数字を設計し、本文を過密にしない。強い表紙、構成で変わる誌面、大きな図形・数字、意図のある動きを使う。すべてを同じ角丸カードと淡色資料へ揃えない。

OSSの原配布書体を提供する。ゴシック、明朝、丸ゴシック、強い見出し書体、英数字書体、コード用の等幅書体を揃え、用途と組み合わせを短く示す。AIへ渡せるデザイン指示と配布元・条件を付ける。技術発表では見出し・説明・英数字・コードを使い分ける。日本語を含まない等幅書体には和文フォールバックを指定し、合字の表示方針も依頼文に入れる。

## 制作と担当

今後の既定モデルはユーザー最新指示によりClaude Opus 5.5（`claude-opus-5-5`）。2026-10-14までの掲載作例はSol 6.1の積極的な並列制作の実績で、その表記を保つ。Astraを使わない。各子は独立した作例・制作スクリプト・fragmentを所有。親は方針・統合・サイトを担当。使っていないモデルを使用済みと記さない。2026-10-15のサイト構成・日本語ガイド・使い方の改訂はOpus 5.5の担当として依頼され、作例の制作バッチとは分けて記録する。

初回の新作はモーションのあるWeb企画資料と誌面風の編集可能PowerPoint。追加制作は別の有用な原典方式にも広げる。コピー、入力、原典、環境、完成ファイルをひと組にする。架空の企画や目標を実績と表示しない。

## 掲載の最小条件

- 原典方式で生成した実ファイルがある。
- 主な出力が開き、明白な欠け・リンク切れを修正。
- 使用commit・方式・改変・書体・個別条件が分かる。
- 作例・日本語スキル・完成資料へ辿れる。

全ページ詳細目視、独立レビュー、全ZIP再実行、構造監査、採点、巨大QAを必須にしない。ビルドと初回表示に確認を絞り、問題がなければ繰り返さない。過去の詳しい確認は履歴とする。

## 正本と完了

方針は `docs/PROJECT.md`、実行目標は `data/project-goal.json`、厳選集は `data/product-collection.json`。原カタログは `data/skills.json`、作例は `data/case-studies.json`、原典の方式は `data/repository-guides.json`。子の成果は独立fragmentから統合する。

方針・閲覧・取得導線を整え、掲載対象ごとに原典方式の日本語作例、入力、利用案内、個別条件を揃える。複数の作風と方式を実制作でカバーする。少数の新作バッチは全体完了に読み替えない。209件を機械的に全消化する条件にせず、有用な原典の追加制作と改良を続ける。

原作者とLICENSE・NOTICEを保持し、カタログのCC0をコードへ広げない。AGPLの対応ソースを保持。OS書体を抽出配布しない。外部公開・merge・deployはユーザー指示に従う。
