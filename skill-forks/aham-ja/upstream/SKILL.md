# Aham PPT 技能 — Aham UI v6.1 · Office 轨 · PPT

## 依赖（Phase 7 转换前确认）

- **必装 pip 包**：`python-pptx`、`cairosvg`（见 `requirements.txt`；缺失时 Phase 7 转换第一步即 ImportError）。
- **可选**：LibreOffice（`soffice` CLI）——用于 PDF 导出与渲染抽检；缺失时交付物**不含 PDF**，在交付说明中注明原因即可，不阻塞 PPTX 交付。
- **字体现实**：规范字体 Inter / JetBrains Mono 若未安装，PPTX 打开时由系统回退（Windows 常见 Calibri/微软雅黑/Consolas），不影响可编辑性；需精确度量请安装 Inter。

> **当前能力概览**（演进史统一见 `CHANGELOG.md`，正文不再按版本叙事）：
> 八阶段强制流程（防跳步 + 卡点等待）× 能力自适应教练机制 × A/B/C 三档视觉主题（含深色模板）。
> 版式库 39 个 ID（6 系 36 个内容版式 + 3 个 SPC 结构页；v4.0 起 16 个通用页型退库走栅格直排，见 grid-composition.md），选择走 layout-library 单一决策表 + 首选核心集；
> 数据强制图表化三环硬门禁。组件层：`charts.py` 14 类数据图表 · `consulting.py` 咨询异形与标注层 ·
> `structures.py` 咨询结构版式（矩阵/树/泳道/蓝图/金字塔等，含 RACI 每行一 A、Mekko ≤7 列等强校验）·
> `themes.py` 结构页 · SVG→原生可编辑 PPTX 工具链 + `tools/lint_svg.py` 预检。
> 有意不落地：雷达图（依据与替代见 layout-library §不提供的图型）。

## Step 1.5 · 选择视觉档（默认 B · 现代专业档）

加载规范后、解析材料前，向用户确认一次视觉档（回车默认 B）：

```
这份 PPT 用哪种视觉档？
  A 克制档     —— 纯白极简，适合高层正式汇报、严谨决策
  B 现代专业档 —— 图标 + 关系图 + 设计化封面/目录/章节（默认，适合多数客户方案）
  C 高表现力档 —— B 的一切 + 深色重音页（封面/章节/金句）+ 数据图表占主导，适合路演/竞标/重点客户（偏“演说稿”，严肃决策仍用 A）
直接回车 = B。
```

记录 `theme = A | B | C`。**三档共用同一套内容与组件**，只切换主题层：A/B 切换封面/目录/章节模板 + 页眉皮肤；C 在 B 之上再叠加深色重音页（封面/章节/金句）。
三档都坚持单一品牌主色 + 中性灰，**不引入多色体系**（多色实测"AI 感/营销感"偏重）。
phase-05（版式）/ phase-07（出片）按 `theme` 取用 `themes.py` 对应模板：A/B 用 `cover/toc/section/chrome`；**C 用 `cover_dark/section_dark/quote_dark`（封面/章节/金句）+ `chrome`（内容页沿用 B 皮肤）+ `charts` 组件（数据页占主导）**。详见 `references/theme-tiers.md`。

## 降级基线（无法读取外部规范时）

> ⚠️ 未找到外部规范，使用内嵌基线（Aham UI v6.1 · Office 轨 · PPT）。

**PPT 核心规则（北极星：极简克制的桌面 AI 气质 · 冷色的纸 · 蓝是点缀）：**
- **底永远纯白 `#FFFFFF`**；三层灰 `#FFFFFF`/`#F3F3F3`/`#E7E7E7`；墨四级 `#262626`/`#6E6E6E`/`#9B9B9B`/`#C4C4C4`。**禁纯黑 `#000`。**
- **蓝 `#336EE8` 只点缀**（品牌点/主操作/选中/推荐/单个高亮数据点/封面短线）；**无顶部蓝条、绝不铺底**。
- Action Title：每页完整结论句、**无衬线 bold `#262626`**（无蓝竖线、无衬线）。
  **写法与用词见 `references/wording-rules.md` §2——主语必须可指认、页间交替、不出现数字、≤24 汉字单行。禁格言警句与对话腔。**
- 字体：**单一无衬线** `Inter, 'PingFang SC', 'Microsoft YaHei', sans-serif`（禁衬线）；数字一律 mono `'JetBrains Mono', Consolas, monospace`。
- 卡片**无边框无阴影**；分块靠留白 + `#E7E7E7` 细横线；选中=扁平灰非蓝。
- 表格**只横线**、无竖线、无整行底色；数字右对齐 mono；表头/合计加粗。状态 = **6px 点 + 文字**（禁红黄绿灯/pill）。
- 图表灰阶 `#9B9B9B`/`#C8C8C8` + **一个** `#336EE8` 高亮；无 3D/阴影/渐变/饼图。
- 标题字号：内容 24pt、封面 32–40pt（左对齐）、正文 14–16pt、大数字 mono 44–60pt。
- 禁用：纯黑#000 / 渐变 / 3D / 投影 / 衬线 / 第二装饰彩色 / emoji / 饼图 / 表格竖线 / 蓝铺底 / 红黄绿灯。
- 禁用词：赋能·颠覆·生态·闭环·最佳实践·全链路·一站式·显著·大幅·承接·沉淀·落地·抓手·粒度·颗粒度·归集·收敛·下沉·对位·波次·地基·命脉·灰度·旁路·水位·卡位（详见「文案措辞」一节）。
- 数字格式：货币 ¥1,200,000；百分比 37.5%；日期 YYYY-MM-DD；数字用等宽 mono。
- 每页一个核心结论，表格优于文字堆砌。

## 附 · 文案措辞（客户不能看出这是 AI 写的）

> 硬要求，不是风格建议。P3/P4/P8 都要照此自查；P8 的「视觉审计」把它列为一项。
> **本节讲通用措辞；Action Title、导语、图内文案、卡片标题的专用规则见
> `references/wording-rules.md`，与本节冲突时以该文件为准。**
> **判据是"这词是不是真的"，不是"够不够浅"**——行业真有的说法直接用、不解释；
> 为表达顺畅凑出来的搭配，再好懂也不能出现。

**词**

- 禁用词见上（降级基线那行）。此外：IT 黑话不进业务 PPT（上下文·下钻·心跳·埋点）。
- **不借外行业的词打比方。**波次（军事）、地基/命脉（比喻）、灰度/旁路（IT 发布）、
  水位、抓手——实测一页里能撞出三个，业务读者一个都读不出来。
- **"形成"不当万能动词**——是签署、登记、记录、取得、生成，就直接说哪一个。
- **一个抽象词只能有一个意思。**实测一份 57 页方案里"口径"用了 17 次、四种意思
  （报表规则/工单定义/产出率算法/报价方式），"适配"用了 34 次。
  第二个意思出现时就换具体词。

**句**

- 单句 ≤60 字。中长句为主，指成分完整，不是拉长。
- 一句一件事，主语和动作都在：谁在做、做什么、做完是什么样。
- **不为对仗砍字。**几个并列项字数接近就是可疑信号——砍掉的往往正是消歧的那部分。
  封面标语最容易犯："承接计划·管好现场·汇聚回传·分步落地"里，
  "汇聚回传"没主语没宾语，"分步落地"是任何项目都成立的废话。

**结构**

- **自造框架词要么定义要么不用。**"五主线""七域""三类适配""P0/P1"是为组织内容造的，
  客户没有这套语言。首次出现一句话讲清它指什么；说不清就是框架本身没想明白，
  拆掉重来，不靠词撑着。
- **小标题按内容起，不套固定栏目。**同一栏目名（如每页都有一栏叫"适配"）
  会逼读者每页重新猜它指什么，也是模板化最明显的痕迹。
- **不凑数。**发现两条写两条，不为"三点"补第三点。凑出来的那条永远最空。
- **强调靠位置和留白，不靠满页加粗。**加粗多了等于没有重点。
- **图表用一句话说清图里是什么，不教读者怎么看图**
  （"横向是八个阶段、纵向是九条泳道、方框是单据"——那是在替读者读图）。

**事实**

- **数得清的写数，数不清的说明白。**写"七类""八个阶段"之前对着内容数一遍。
  实测出过"说七类只列了六项""说八个阶段表里只有六个"。
- **符号必须有图例。**用了 ☆★ 就在表下写清两者区别，抄表时最容易漏掉这句。
- **现状不等于目标。**"某事现在做不好"推不出"本期要把它做好"——
  哪些进目标是客户定的，不能从现状反推。
- **没调研到的正面写出来**（"夜班情况待确认"），不是不写，也不是含糊带过。
  前期方案里 AI 味的主要表现不是用词花哨，是过度确定和过度整齐。

## 附 · 工程预检与防坑（实战复盘沉淀）

> 大体量册子（数十页、含信息图）批量生成时，以下几类坑会反复出现。**渲染前后各跑一次 `assets/tools/lint_svg.py`**。

1. **字符安全（防 tofu □）**：序号用「圆圈 + 阿拉伯数字」，不要用 ①②③；对错用 √(U+221A) / ×(U+00D7) 或画 path，不要用 ✓✕；MONO/等宽文本只放 ASCII。**源码文案一律用「」，不要用中文双引号 “”（会截断字符串、触发 SyntaxError）**。
2. **图标**：一物一图标、命名即语义；新增或修改图标后先跑 `assets/tools/icons_preview.py` 出缩略表肉眼核对。具象制造业图标库见 `assets/components/mes_icons.py`（worker/conveyor/andon/gearmold/injection… 共 25+）。
3. **页码**：各页页脚写统一占位（chrome 的 page 传 "—"、total 全册同一个数），最后用 `assets/tools/pageno_fill.py` 一次性回填，**不要在各脚本各写 total**（否则出现 /50 与 /57 并存）。
4. **软件界面未到位**：用 `components.placeholder()` 占位框，不要硬编假 UI（等真实截图替换）。
5. **术语一致**：开工就建项目级 canonical 术语表（同一事物只用一个名，如线材/磁线只留一个、SN 与序列号统一）。
6. **事实准确**：先建《项目基线》（来源分层、客户确认白名单、缺口标"待确认"、**绝不编造数字**），所有页引用它；交付前做 **双轨审计 = 内容审计（逐页对基线，含架构/主线/场景）+ 视觉审计（排版/色/矛盾/错别字/重复/自造词）**，批准后再改。
7. **客户已评审的图为锚**：客户确认过的架构图/口径设为不可推翻，其余页向它对齐。
8. **每页独立信息图**：同一章节相邻页不得套同一骨架（流程/对比/矩阵/空间/仪表轮换），避免"模板化"。
