## 执行步骤

### 步骤1：五层质检

> 先 `view references/quality-audit-protocol.md`：其 §三「交付前人工审计流程」（HTML 预览审查 / PPTX 抽样检查 / QC 报告模板）在本阶段执行。
> **权威分工**：视觉合规逐项勾选详单以 quality-audit-protocol §三为准（本文件不复写）；机判项（色值精确比对、图文重叠、字体扫描）以本文件 L2 为准。

按以下五层规则执行检查：

**L1 · 叙事质量**
- 灵魂句贯穿全文：所有内容页标题串读仍形成逻辑链，且指向灵魂句
- 执行摘要完整性：第2页包含SCQA的核心答案
- 受众关注点已回答：Phase 1受众卡中的核心关切在对应页面有明确回答
- Action Title字数：所有内容页标题≤30字
- 标题↔证据支撑：逐页核对 Action Title 的每个断言是否被页内数据/证据支撑；标题强于证据（超卖页）判 ERROR
- 一页一消息：每页核心信息唯一（判据=标题不含两个可独立证伪的断言；「和/与/并且/同时/且/及/顿号」仅为复查信号，单结论多依据不算双消息）
- narrative_purpose（叙事目的）完整性：所有页面有标注

**L2 · 格式一致性**
- 全局页脚存在（页码/版本/日期）
- Action Title 字体正确（**无衬线 Bold**：Inter / 微软雅黑；**出现宋体/任何衬线即 ERROR**）
- 页眉 `#E7E7E7` 细线存在；**无顶部蓝条、无 Action Title 蓝竖线**（出现即 ERROR）
- **品牌色精确比对**：扫描所有SVG中的 `fill` / `stroke` 色值，与 BRAND_RULES 精确匹配（如 `#336EE8` 不得写成 `#003D77` 或 `#003d7a`，大小写不一致也需修正为大写）
- **字体一致性逐页扫描**：检查每页 Action Title 字体是否统一，正文字体是否统一，不得在同一类别文字里混用字体；数字用 mono（Consolas / JetBrains Mono）
- **图文重叠检测**：检查文字元素的 `y` 坐标是否落在其他 `<rect>` 或图形区域内（坐标重叠判定：文字 y 值位于某个 rect 的 y 到 y+h 范围内，且 x 值位于 rect 的 x 到 x+w 范围内，则标记为疑似重叠，请人工确认）
- 图表配色：数据元素灰阶 + 至多一个 `#336EE8` 高亮，**正负不用红绿区分**（瀑布等用灰阶 + 符号/方向）；KPI/状态的语义色须配 6px 点 + 文字双通道，数值本身不染红绿
- 术语一致性（同一概念用词统一，扫描全文找同义词）
- **措辞自查（对照 SKILL.md「附 · 文案措辞」，逐项过）**：
  - 全文搜禁用词（承接·赋能·沉淀·落地·抓手·闭环·波次·地基·灰度·旁路…）
  - 一词多义扫描：口径、适配、覆盖、支撑、维度、机制——同一个词是不是在讲不同的事
  - 自造框架词（五主线/七域/P0 等）在首次出现处有没有一句话定义
  - 并列项字数是否几乎相等（是则检查有没有为对仗砍掉消歧的字）
  - 所有带数字的清单实际数一遍（"七类"是不是真有七项）
  - 用到的符号（☆★√×）表下有没有图例
  - 单句 >60 字的逐句拆开

**L3 · 专业交付**
- 数据来源标注（所有图表和数据有来源）
- 禁用图表类型检查（无饼图/环形图）
- 柱状图Y轴从0开始
- 封面元数据完整（委托方/版本/日期/保密标注）
- 文件数量验证（SVG文件数=规划页数）
- **脱敏检查**：全文无真实人名 / 第三方公司名 / 内部项目代号（已换"角色 / 同行 / 某企业 / 某真实项目"）

**L4 · 视觉节奏**（阈值唯一源见 `layout-library.md §节奏约束`）
- 单页信息密度不超过deck_mode上限
- 10页滑动窗口版式系别多样性≥5种
- 每10页至少1页impact类
- 每8-10页至少1页transition类
- 连续3页无相同版式系别

**L4.5 · 版式合规**（兜底 Phase 5 选版式，逐页核对）
- **主角↔版式匹配**：每页『视觉主角/narrative_purpose』与所选版式是否符合 `layout-library §版式选择速查`（不符 → WARNING，回 Phase 5 改版式）
- **数据未被文字化**：聚集 ≥3 条 D 类数据的页，是否真用了 charts 图表而非纯文字卡/纯表格（违反 → ERROR）
- **图形化占比达标**：连续纯文字版式 ≤2 页；全册数据图表页 ≥ ⌈内容页数/6⌉（低于线 → WARNING）
- **无废弃版式 ID**：不出现历史退役 ID（原 I-02/I-03/V-01/SPC 骨架，及 v4.0 移出的原 I-01/I-05/T-01/T-02/T-03/S-01/S-03/S-04/S-05/S-06/S-08/S-12/E-01/A-01/A-02/G-02——这些内容页应标「直排」而非版式 ID）

**L5 · 视觉呈现**
- 坐标重叠检测（文字/图形无非预期重叠）
- 元素遮挡检测（内容区无被遮挡的重要信息）
- SVG与PPTX版本一致（如两者都有）

**处理规则：**
- ERROR级：必须修复，阻断交付
- WARNING级：展示给用户，用户选择：修复 / 带注释交付 / 忽略
- INFO级：仅提示，不阻断

### 步骤1.5：渲染目检（LibreOffice 可用时；对标官方 pptx 技能的渲染 QA 闭环）

lint 与五层 QC 管不住「重叠感/拥挤感/节奏单调」这类主观项——用渲染图逐页目检补上：

```bash
soffice --headless --convert-to pdf 方案.pptx --outdir ./qc_render/
# 再用任一 PDF 转图工具逐页出 PNG（如 pdftoppm -png），逐页目检：
# □ 无图文重叠感/拥挤感  □ 相邻页不同骨架（防模板脸）  □ 深浅节奏符合规划
```

发现问题 → 回 Phase 7 修对应页 SVG 重转（SVG 是唯一真源，不直接改 PPT）。LibreOffice 缺失 → 跳过本步并在交付说明记录。

### 步骤2：QC报告生成

将质检结果整理为用户友好的报告格式（不展示技术细节，只展示问题和建议）：

```
QC报告 · [项目名称]

ERROR（必须修复）：
  · [页码] [问题描述] → [修复建议]

WARNING（建议修复）：
  · [页码] [问题描述] → [修复建议]
  你的选择：A.修复  B.带注释交付  C.忽略

INFO（供参考）：
  · [描述]

技术质检已通过项：
  ✓ 格式一致性
  ✓ 数据来源标注
  ✓ 视觉节奏
  （列出通过的项）
```

---

### 步骤3：问题处理

对ERROR级问题：
- AI给出具体修改建议
- 修改后重新执行相应的QC层
- 全部ERROR修复后才能继续

对WARNING级问题：
- 用户选择A（修复）→ 执行修改
- 用户选择B（带注释）→ 在交付报告中标注"已知问题"
- 用户选择C（忽略）→ 记录在final_report.md，继续

---

### 步骤4：交付物打包

所有QC问题处理完成后，打包交付物：

```
📦 交付物：
- 方案.pptx      （原生可编辑PPT，客户双击即改）
- 方案.pdf       （打印分发版，从PPTX导出）
- 方案.html      （浏览器预览版，可分享链接）
- svg_final.zip  （SVG真源文件，单一可信源）
- final_report.md（项目报告，含决策记录和已知问题）
```

根据output_format选择性输出：
- svg → 只输出svg_final.zip + preview.html
- pptx-native → 只输出方案.pptx + final_report.md
- both（默认）→ 全部输出

---

### 步骤5：最终交付说明

交付时输出：

```
技术质检已通过：
  ✓ 格式/规范/一致性
  ✓ 视觉节奏
  ✓ 视觉呈现

以下需要你做最终判断，QC无法替代：
  · 每页内容的说服力是否足够
    （格式合规不等于说服力足够）
  · 叙事角度是否真正契合这个受众的决策逻辑
  · 有没有哪页感觉"对但没用"，需要换角度

[已知问题说明，如有]
```
