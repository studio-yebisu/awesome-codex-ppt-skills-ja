## 执行步骤

### 步骤1：金字塔论证树构建

**金字塔结构（三层）：**

```
第一层（顶）：灵魂句（唯一，来自Phase 3）
    ↓
第二层：支撑论点（2-4个，MECE）
    ↓
第三层：证据层（每个论点对应2-3个证据，来自Phase 2信息清单）
```

**第二层论点构建原则：**

优先从反对意见反推论点：**教练/引导模式**用 Phase 3 压力测试（coach-engine 步骤5）识别的反对意见；**专家模式**（Phase 3 未单独跑压力测试时）直接取受众卡的『主要顾虑』作为反对意见来源。
每个反对意见对应一个需要在PPT里消除的顾虑，也就是一个论点。

**论证模式与排序（先定，写入完成卡）：**
- **归纳分组（默认）**：3±1 个并列论点共同支撑灵魂句。分组后按 Minto 四种次序之一排列：**演绎次序**（前提→推论）/ **时间次序**（步骤先后）/ **结构次序**（空间/组成部分）/ **重要性次序**（受众最关心的在前，默认取此）。所选次序写入规划卡。
- **演绎链（少用；论证强依赖逻辑推导时）**：大前提 → 小前提 → 结论，链上每环一章，链长 ≤3 环；材料撑不起任一环时退回归纳分组。

常见论点组合模式（供参考，不强制）：
- 必要性 + 可行性 + 紧迫性
- 问题定性 + 解决方案 + 实施路径
- 现状分析 + 目标定义 + 行动建议

**MECE检验（互不重叠、合计完整）：**
- 互不重叠：任意两个论点是否在说同一件事？有则合并
- 合计完整：三个论点合在一起，是否足够证明灵魂句？有漏洞则补充

### 步骤2：Action Title（结论式标题）写法

> **完整规则见 `wording-rules.md` §2。本节只保留要点，冲突时以该文件为准。
> 下面例子里的模块名一律是占位符。**

**定义：** 每页标题是结论性陈述，而不是话题描述。读完标题，受众已知道这页的核心信息。

**两种不合格，都要避开：**

```
话题词        现场数据自动化
格言警句      外部追问每年都会来，取数成本取决于数据是不是同一套
合格          〈报表模块〉可按六个披露方向输出数据与追溯记录
```

原规则只禁了话题词，实测会滑向格言与对话腔。两个方向都要挡住。

**硬要求（逐条 grep）：**

| # | 要求 | 说明 |
|---|---|---|
| 1 | 主语可指认 | 只能是「系统」、具体模块名或客户名。禁「外部追问」「取数成本」「关键」「源头」这类抽象名词 |
| 2 | 主语页间交替 | 不得连续两页同一主语。对得上模块就用模块名，对不上才用「系统」 |
| 3 | 客户名按内容带 | 讲客户自己的资产或既有事实时带，讲我方能力时不带 |
| 4 | 情态词按验证状态 | 未在本客户验证的能力用「可」；已验证的事实与客户既有事实写确定式 |
| 5 | 不出现数字 | 客户经营数字与系统参数都不进标题。分组数量词（四种经营模式）不算 |
| 6 | ≤24 汉字，单行 | |
| 7 | 至多一个逗号 | 两个分句必须同一主语 |
| 8 | 禁用清单 | 格言警句、「不是 A 而是 B」、比喻、反问设问、祈使建议、抽象主语、评价句 |

**改写实例：**

| 原（不合格） | 改后 |
|---|---|
| 业务量一年接近翻倍，先看架构撑不撑得住，再看功能 | 〈主数据模块〉可按多组织与多账簿分层扩展，不需重建账套 |
| 扩产要同时支持四种模式，不是把同一条产线复制一遍 | 〈客户简称〉的四种经营模式可在同一套主数据上分别配置 |
| 外部追问每年都会来，取数成本取决于数据是不是同一套 | 〈报表模块〉可按六个披露方向输出数据与追溯记录 |
| 计提比例已到 22%，要把识别时点从年末提到日常 | 〈库存模块〉可按批次计算库龄并预测呆滞金额 |
| 自研执行系统保持不动，先把边界与回传口径定下来 | 〈客户简称〉的自研执行系统保持不动，由本系统接收其回传结果 |
| 工程数据的源头放在哪里，决定了计划与成本准不准 | 〈研发模块〉可控制物料与清单版本的生效范围 |
| 九个人管一家上市公司的账，人力要放在判断上而不是搬运上 | 系统可将结账、报表与审单交由智能体处理，人工只处理例外 |

**Ghost Deck 交付前必做：** 把全部标题抽成一列通读，检查主语是否可指认、
有没有连续两页同一主语、腔调是否一致。这一步不可跳过——腔调问题只有在
标题连读时才看得出来。

### 步骤3：Ghost Deck页面结构

**标准页面顺序：**

```
页1   封面          PPT主标题（非Action Title，是项目名/汇报名）
页2   执行摘要      SCQA的A精华，第一个让受众看到结论的地方
页3   目录          章节结构概览
页4   章节过渡页    第一部分：章节Action Title
页5+  内容页        内容页Action Title（每页≤30字结论）
...   章节过渡页    第二部分：章节Action Title
...   内容页        内容页Action Title
...   结尾行动页    受众预期行动的明确呼吁
```

**页数分配：**
```
内容页数 = 总页数 - 4 - 章节数
（封面1 + 执行摘要1 + 目录1 + 结尾1 + 各章节过渡页各1）
```

**论点→页面折算规则：**
- 第二层论点 = 章节（一论点一章，隐式规则至此明文化）；
- 第三层证据按 **1–2 条/页** 折页；
- 页数按**受众顾虑优先级加权**：受众卡「主要顾虑」所对应论点的章节页数 ≥ 其他章节。

**narrative_purpose（叙事目的）标注：**
每页必须标注以下6类之一：
- impact（震撼）：震撼性数字、关键结论
- structure（结构）：目录、章节过渡、框架说明
- explain（说明）：流程、方案、方法论解释
- evidence（证据）：数据、案例、验证
- transition（过渡）：章节衔接、节奏调剂
- action（行动）：结尾行动页、建议清单

**节奏要求：**
- **深色重音页编排（C 档）**：选 C 档时，在 Ghost Deck 阶段就规划深色页位置 —— 章节过渡页可用深色（section_dark），关键结论 / 金句单独成深色页（quote_dark），形成“白—白—深”的三明治节奏；避免连续 ≥3 页同色调。深色页计入节奏起伏，不额外增加内容页计数。
- **内容层张力（C 档，对标 Duarte sparkline）**：每章 ≥1 组「现状（what is）→ 愿景/目标（what could be）」对比结构——用 VS 对照直排页（grid-composition §VS）、V 系前后对比（slope/双图）、或「现状页 + 深色金句页」相邻编排实现；在 Ghost Deck 标注每章对比组的位置，与深色重音页编排合并执行（视觉节奏管色调，本条管内容弧线，两者独立检查）。
- 版式多样性 / impact 频率 / transition 频率等节奏阈值，以 `layout-library.md §节奏约束` 为唯一来源。

### 步骤4：Ghost Deck五项测试

生成完整标题序列后，执行以下五项测试：

**测试1 · 只读标题测试**
将所有页面标题连起来读，不看正文。
通过标准：读完标题序列，受众已能理解「为什么要做这件事、做什么、怎么做、结果如何」。
不通过特征：读完只知道「讲了哪些话题」。

**测试2 · MECE检验**
同一章节内的各内容页标题检验：
- 互斥性：任意两页是否在说同一件事？有则合并
- 完备性：合在一起是否完整证明章节Action Title？

**测试3 · 灵魂句回溯**
对每一页标题问：「这页在支撑灵魂句吗？」
如果这页的内容无论对错，都不影响灵魂句成立 → 冗余页，删除或移入附录。
若受众卡登记了**次要受众**：每个「否决点」是否有对应页或附录？没有 → 补页，或在既有页明示回应。

**测试4 · Action Title检验**
对每一页标题检验：
- 是结论陈述，还是话题描述？
- 读完标题，是否已知道这页的核心信息？
- 标注需要改写的标题，给出修改建议。

**测试5 · 证据配对（全模式强制，含专家模式）**
逐论点从 Phase 2 信息清单匹配证据，标注：绿=有充分证据 / 黄=证据弱需补充 / 红=无证据。
- **红色论点不得进入 Ghost Deck**：补证据、降级为「假设」并在页面明示，或删除该论点。
- 本测试不因档位豁免；教练/引导模式的执行话术见 coach-engine「Phase 4」步骤4（判据与此处同源）。

**测试处理规则：**
- 全部通过 → 生成完成卡，放行
- 测试5 出现红色 → 必须先处理（补证据/降级为假设/删除），不计入下述3次迭代
- 有问题 → AI自行修改问题标题，重新测试，最多迭代3次
- 3次后仍有问题 → 标注问题，在完成卡中列出，让用户决策
