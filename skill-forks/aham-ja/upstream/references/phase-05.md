# Phase 5 · 大纲内容与版式规划

> 本阶段是八步流水线的**必经一步**（不可跳过 / 不可与其它阶段合并产出）；文件本身可独立维护。
> ▶ **进入本阶段第一句先输出**：`【阶段 5/8 · 大纲与版式规划 · 已加载 phase-05.md】`
> 本Phase将Ghost Deck的标题骨架填充为每页的内容要点，并同步确定每页的版式。
> 内容填充和版式选择必须同步进行：内容类型决定版式，版式反过来约束内容密度。
> **页内文字规则见 `wording-rules.md` §3：分区小标题按本页内容起；判断句与收口一律
> 不写；导语只在小标题未交代分组时才写；表格只用于两个以上对象的横向对比；
> 并列信息格按「小标题 → 结论句 → 列表」三层组织。**

## 执行步骤

### 步骤1：deck_mode（交付模式）确认

读取Phase 1记录的deck_mode推断，向用户二次确认：

```
基于你的描述，我判断这份PPT的交付模式是 [hybrid/presenting/reading]。

影响：
- 每页信息密度控制在 [60-80% / 40-60% / 80-95%]
- 至少10%的页面为震撼类（单数字大屏/引言等）
- 10页滑动窗口中版式系别多样性≥5种（见 layout-library §节奏约束）

确认[X]，还是调整？
```

交付模式说明：
- presenting（演讲为主）：路演、发布会、演讲，以讲者口头展开为主，页面留白多
- hybrid（混合，默认）：客户汇报、顾问报告，现场讲解+会后带走
- reading（阅读为主）：分析报告、白皮书，脱离讲者也能独立理解

### 步骤2：逐页布局规划卡

**强制等待锚点：** 输出全部布局规划卡后，必须停止，等待用户回复确认后才能进入 Phase 6。不得在用户确认前自动继续生成任何设计内容。

为每一页生成布局规划卡（坐标字段来自 `grid-system.md`，Phase 7 直接使用不再计算）：

```
页码：[X]
Action Title：[标题]
叙事目的：[impact/structure/explain/evidence/transition/action]
视觉主角：[大数字/对比关系/流程图/数据图表/矩阵框架/引言文字/结构分解]
内容要点：
  · [要点1]（≤[单行字数上限]字）
  · [要点2]
  · [要点3]
数据来源：[如有，列出需要标注的来源]
讲者备注（presenting/hybrid 模式必填）：[被密度上限挤出页面的内容要点，交付时写入 PPTX 备注栏]
推荐版式：[版式ID]
  骨架文件：svg-skeleton-[系].md → [版式ID]章节
  区域坐标：[从grid-system.md复制的精确坐标，如"左栏 x=40,y=100,w=592,h=580"]
备选版式1：[版式ID]
备选版式2：[版式ID]
版式自检（每页必勾，见步骤2.5）：
  □ 数据 ≥3 条 / 可对比排序 / 时间序列 → 已用 charts 组件（否则改 V 系，不得文字化）
  □ 非数据页 → 已判断能否用结构图(E/G)/关系图组件（能则优先；纯文字版式须写明"无可图形化内容"）
  □ 视觉主角 ↔ 推荐版式 匹配（取自 layout-library §版式选择速查）
```

**坐标字段是Phase 7的设计依据，Phase 7不再自行决定坐标。**
**"版式自检"三项未全部满足，本页布局规划卡不算完成——不得进入 Phase 6。**

**按视觉档（theme）选结构性页模板（来自 Step 1.5，Phase 1 已记录）：**
- A / B 档：封面/目录/章节用 `themes.py` 的 `cover/toc/section`，内容页用 `chrome` 皮肤（B 档含图标/关系图组件）。
- C 高表现力档：封面/章节/金句改用深色重音模板 `cover_dark/section_dark/quote_dark`，内容页仍用 `chrome`(B 皮肤)，数据页用 `charts` 组件占主导，并按 Phase 4 规划穿插"白—白—深"节奏。
- 在每页布局规划卡的"推荐版式"旁注明本页所用 theme 模板/组件，供 Phase 7 直接调用。

**版式选择 → 查 `layout-library.md` §版式选择速查（内容类型→版式 的唯一权威决策表）**：
按本页『视觉主角』在该表取**首选版式**，优先用表头列出的「首选核心集」；**不要在本文件或别处另立一套映射**。
封面/目录/章节等结构性页按上方 theme 走 `themes.py`，不在此表内选。

> **两级选择逻辑（v4.0）**：①内容命中版式库触发条件（连接线锚点/落位/咬合/硬校验类，见 `layout-library.md` 速查表）→ 查表选版式，版式 ID 即骨架文件章节名（如 S-02 对应 svg-skeleton-s.md 的 `## S-02` 章节），每章节以**五栏**（用途/适用场景/用法/来源/纪律）给出实现路径（`layouts.py` / `consulting.py` / `structures.py` / `charts.py`）；②纯并列/对照/大数字/过渡等低自由度内容 → **不查表**，按 `grid-composition.md` 直排（结构要点与纪律见其 §二）。**全库无照抄式冻结骨架**。**例外**：封面/目录/章节由 `themes.py` 生成（不在 svg-skeleton 里，别找 svg-skeleton-spc.md）；数据图表用 `charts.py` 组件（不是独立版式系）；标注层（圈注/引线/水印/So-What）纪律见 `svg-skeleton-common.md §咨询密集层 D`，可叠加任意版式。

### 步骤2.5：图形化优先 + 数据强制图表化（防平淡）

每页布局规划卡定稿前逐页执行：

1. **数据强制图表化**：若该页聚集 **≥3 条 D 类数据**（Phase 2 标注、带数值），或含可对比/可排序/时间序列的数字 → **该页必须用数据图表，禁止用纯文字卡或纯表格承载多条数据**。按形态选 charts 组件（**14 类**：bar/hbar/line/waterfall/funnel/gantt/bullet/stacked/slope/sparkline/kpi_card/marimekko/fte_ramp/horizon_curves，均一行调用；**触发条件与权威清单以 layout-library.md 速查表 + chart-impl.md 为准，本处不再维护第二份映射**）。版式记 V 系并写明调用的组件名。
2. **图形化优先**：非数据页先判断能否用结构图（E 系流程/架构、G 系树/金字塔）或关系图组件承载；能则优先。**纯文字排列页（grid-composition 直排类及 HERO S-07·N=2/3/4）退为兜底**，选它须在规划卡写明“此页无可图形化内容”。
3. **图形化占比下限**：连续纯文字排列版式不超过 2 页；每 8 页内 ≥2 页含数据图表（V 系 / charts）或结构图（E/G 系）；全册数据图表页 ≥ ⌈内容页数 / 6⌉。低于线 → 回查是否有 D 类数据被文字化。

### 步骤3：信息密度控制

根据deck_mode设置每页内容密度：

| deck_mode | bullets上限 | 每条字数上限 |
|-----------|------------|------------|
| presenting | ≤3条 | ≤15字 |
| hybrid（默认） | ≤5条 | ≤20字 |
| reading | ≤7条 | ≤30字 |

一页一消息强制检验：
每页只传递一个核心信息。**判据（语义）**：标题是否含**两个可独立证伪的断言**？是 → 拆页。
词表信号（仅提示复查，非判据）：「和/与/并且/同时/且/及/顿号并列」；**单一结论 + 多条并列依据不拆**（如「Q3 是唯一窗口：A、B、C」是一个断言）。

---

### 步骤4：视觉节奏检查

全部规划卡生成后执行（阈值唯一源见 `layout-library.md §节奏约束`）：
- 连续雷同检测：连续3页不能使用相同版式系别
- 震撼类检查：每10页至少1页impact类
- 过渡类检查：每8-10页至少1页transition类
- 多样性统计：10页滑动窗口内，版式系别种类≥5种

## 跳过风险

```
风险等级：中
风险说明：
  跳过版式规划，Phase 7设计时即兴选版式，
  容易导致全PPT视觉单调（只有上下分/左右分）。
  更大的风险：内容和版式不匹配，设计阶段大量返工。
  在这里批量确认版式，比设计后修改快得多。
```
