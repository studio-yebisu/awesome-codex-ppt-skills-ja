# 用词风格规则

> **适用范围**：本技能生成的 PPT 全部文字——Action Title、分区小标题、导语、
> 并列信息格、列表、图内文案、卡片标题、说明句。不管其他交付物。
>
> **与其他规范的关系**：通用写作规范（禁用词表、段落长度、序号写法、括号用法、
> 缩写展开）以用户的 userPreferences 为准，本文件不重复。`SKILL.md`「文案措辞」
> 一节讲通用措辞；与本文件冲突时以本文件为准。
>
> **例子里的公司名与模块名一律是占位符**，写作时替换为项目实际名称。
> 本文件不得写入任何真实客户名、真实产品名或真实项目数据。

---

## 一、通则

### 1.1 一句话总则

**是在告诉某个具体的人一件事，不是在描述一个话题，也不是在讲道理。**

判不准时回到这句。描述话题会产生名词短语；讲道理会产生格言与对话腔。两者都不合格。

### 1.2 两类失败模式

技能早期只禁了话题词一个方向，实测会从这个方向逃向另一个极端。两个方向都要挡住。

```
话题词        现场数据自动化
              —— 没有动词，读者不知道谁做、做完什么样

格言警句      外部追问每年都会来，取数成本取决于数据是不是同一套
              —— 有动词、有主谓，但主语是抽象名词，句子在讲道理

合格          〈报表模块〉可按六个披露方向输出数据与追溯记录
```

### 1.3 对话与交付物分开

**对话中的口头分析不得直接搬进交付物。** 这是本技能最常见的失效路径：先在对话里
跟用户口头分析，再把那个腔调原样写进页面。对话可以口语，交付物不可以。

## 二、Action Title

### 2.1 主语

**主语必须是可指认的对象。** 只有三类可以作主语：

| 类别 | 说明 | 占位示例 |
|---|---|---|
| 系统 | 泛指本次交付的系统整体 | 系统 |
| 具体模块名 | 产品线里真实存在的模块 | 〈成本模块〉〈库存模块〉〈报表模块〉〈集成平台〉 |
| 客户名 | 客户简称，或「贵司」 | 〈客户简称〉 |

禁止作主语的抽象名词：外部追问、取数成本、业务量、扩产、关键、源头、边界、
口径、变动——这类词一律不许开头。

### 2.2 主语在页与页之间交替

不得连续两页用同一个主语。这一页的内容对应得上具体模块，就用模块名；对不上，
才用「系统」。

```
正确的节奏
  〈主数据模块〉可按多组织与多账簿分层扩展，不需重建账套
  系统可在同一套主数据上支持四种经营模式
  〈研发模块〉可控制物料与清单版本的生效范围
  系统可在同一张委外工单上记录发料、回收与结算
```

### 2.3 客户名什么时候出现

讲客户自己的资产、组织或既有事实 → 带客户名。
讲我方系统能力 → 不带。

```
带      〈客户简称〉的自研执行系统保持不动，由本系统接收其回传结果
不带    系统可按多组织与多账簿分层扩展，不需重建账套
```

同一份材料里出现两次以上客户名是允许的，不必为了避免重复而删。

### 2.4 谓语与情态词

> 本节适用于全部文字，不只是标题。正文、卡片、图内说明同样适用。

- 我方系统能力，且未在本客户实施验证过 → 用「可」
- 我方已在本客户实施验证过的事实 → 写确定式
- 客户的既有事实 → 写确定式，不加情态词

```
系统可按批次计算库龄            （能力，未验证）
自研执行系统保持不动            （客户既有事实）
```

### 2.5 标题不出现数字

客户的经营数字不进标题，系统参数也不进。数字留在页内。

```
不合格   计提比例已到 22%，要把识别时点从年末提到日常
不合格   〈库存模块〉可按批次计算库龄，并预测未来三个月的呆滞金额
合格     〈库存模块〉可按批次计算库龄并预测呆滞金额
```

**例外**：分组数量词写在主语里是允许的（四种经营模式、三条产品线、六个方向），
因为它限定的是主语范围，不是在摆数据。

### 2.6 长度与断句

- 不超过 24 个汉字
- 必须单行
- 至多一个逗号，两个分句必须是同一主语

## 三、页内文字

### 3.1 分区小标题按本页内容起

页内的分区小标题必须写这一区讲的具体内容，不用固定栏目名，不用设问句。
同一个栏目名在多页重复出现，读者每页都要重新猜它指什么，也是模板化最明显的痕迹。

```
不合格   〈产品名〉怎么实现            （设问，且每页重复）
不合格   实现方式 / 对应做法          （固定栏目名）
合格     两套系统的分层对比
合格     四种经营模式的单据主线
合格     毛利变动的三个来源
```

### 3.2 导语

小标题写清楚之后，导语往往就多余了，删掉。
**只有当小标题没有交代分组名称时才写导语，并把分组名称写全。**

```
写      以下按研发设计、零件加工、批量制造、装备项目四种模式，
        分别说明单据主线与对应模块
不写    以下按四种经营模式分别说明        （分组名称没写全）
不写    毛利率是结果，不是原因            （无分组，且是判断句）
```

### 3.3 并列信息格的三层结构

三格并排的信息区，每格必须分三层，不得写成同色同字重的长段落：

```
〈分组名〉                              ← 小标题：这格讲什么。左对齐，12px，加粗
      〈本格的一句结论〉                ← 结论句：格内居中，13.5px，加粗，墨色
· 可逐条核对的事项一                    ← 列表：左对齐，12.5px，次级灰
· 可逐条核对的事项二
· 可逐条核对的事项三
```

- 小标题按本页内容起，不套固定栏目名。列头与小标题二选一，不并存。
- 结论句在各自格内居中，是全格唯一的视觉落点。
- 列表只放可以逐条核对的事项，每格二到三条。

### 3.4 列表与表格

- 列表只给能被单独核对或反驳的事项，不给有先后依赖的步骤。步骤用流程图。
- 表格只用于两个以上对象的横向对比。单个对象的内容用段落，不用表格。
- 一页的信息块数量不限，版面放得下即可。

### 3.5 判断句与收口一律不写

页内不写作者的判断、提醒、风险提示与经验之谈。表画完、图画完，这页就结束。
页面底部不加总结句。

```
不写   边界不清是这类项目最常见的返工原因
不写   四种模式如果分散在不同系统，成本口径就无法合并看
不写   为什么这条要先谈
不写   关账前要拦住的两件事
```

这些内容属于口头讲解，写进页面就变成作者在页面上说话。

### 3.6 交付物里不写「待确认」

给客户看的页面上不出现「待现场确认」「待补充」「待定」这类字样——它等于告诉客户
这份材料没做完。需要向客户了解的内容，写成问句，并把这一列的列头或小标题改成
「本次要了解的情况」，让读者一眼看出这是议题而不是结论。

```
不合格   各段工作分别占用多少人力，待现场确认
合格     各段工作分别占用多少人力，哪一段最影响月结时间
```

对内的调研提纲不受此限。

### 3.7 举例的清单要写「等」

方案与前期材料里列举几项时必须加「等」，否则读者会读成只有这几项。
技术协议与 SOW 里的封闭清单必须精确，不加「等」。

举例还要挑最常用的几项，不要只列自己顺手想到的那几个。

```
不合格   物料、清单、工艺路线、成本对象，由总部统一定义
合格     物料、清单、客户、供应商等核心基础资料，可由总部统一定义
```

### 3.8 卡片与小块的文字必须能独立读通

名词短语当标题时，下面那行必须补齐主语和动作。只丢几个名词，读者拼不出完整意思。
凑不出两层就合成一句话，不分标题与说明。

```
不合格   并存的三种成本对象
         工单、批次、项目
合格     工单、批次与项目三种成本对象可在同一账簿下并存，各产品线按自身模式取用
```

### 3.9 不堆叠修饰语

一个动作最多带一个修饰。四段修饰叠在一起就成了机器话。

```
不合格   三大报表自动勾稽全量检查        （自动 + 勾稽 + 全量 + 检查）
合格     三大报表一键生成，勾稽关系逐项自动核对
```

判据仍是 §1.1 与 §5 的总则——行业真有的说法直接用，为表达顺畅凑出来的搭配不许出现。
「全量检查」是凑出来的，「勾稽」是会计的真词，可以用。

**三个同类项并列不算堆叠**（如「库龄分析、根因追溯、呆滞预测」），是正常的并列举例。

## 四、图内文案与卡片

### 4.1 方框标签

允许名词短语，但必须是真实的单据名、业务对象名或系统模块名。
用完整规范术语，不用简称。

```
合格     财务报表 → 会计凭证 → 业务单据 → 单据附件
不合格   报表 → 凭证 → 业务单据 → 附件与接口记录
```

### 4.2 禁止自造概念

图里不得出现为了表达顺畅而临时造的名词。发现自造概念时，**换成一个看得见的
对象名，不要换成动作名**。

```
状态门        →  〈清单〉版本状态        （对象；不要写成「版本生效校验」这种动作）
解耦点        →  半成品缓存
净需求计算    →  净需求                  （「净需求」是计划领域的标准说法，可用）
```

### 4.3 卡片标题

动宾结构，不带主语，不带口语。省略的主语必须是本页标题里已经出现过的对象。

```
合格     统一库龄口径 / 追溯呆滞原因 / 预测呆滞金额
不合格   呆滞原因可以查到人                    （口语）
不合格   库龄口径 / 呆滞原因 / 呆滞预测        （名词短语，无动词）
```

**动词必须是日常动词，不许把名词硬当动词用。** 统一、追溯、预测、控制、保存
本来就是动词，可以用；标识、留存、赋权、归口是名词硬当动词，不许用。
凑不出日常动词时把标题写长一点，不要为了短而生造。

```
不合格   标识关联方        →  在客商档案标注关联方
不合格   留存定价依据      →  保存定价依据与审批记录
```

### 4.4 并列项必须真正同级同类

图里几个框放在一起，读者会默认它们是同一层的同类东西。凑数量、凑对称把不同
层级的东西并排，是这类图最常见的错误。

```
不合格   业务层 / 数据层 / 分析层 / 接入层
         前三个是上下层关系，第四个是横切的，不在同一条线上
合格     改为两列对比表：客户端 / 组织与账簿 / 数据库 / 报表取数 /
         外部系统接入 / 技术支持，每行左右各一个值
```

**判断方法：给这组并列项起一个共同的上位名称。起不出来，就是不同级。**

### 4.5 同一组并列项中不要只有一项带数字

一组并列项里只有一项写了具体数字，其余都没有，读者会读成「这一项特别重要」。
要么每项都有可比的数字，要么都不写，数字放到页面其他位置。

```
不合格   票据台账    313 张、182 家出票人；544 张、298 家出票人
         往来对账    客户与供应商余额、发票与收付款核销
合格     票据台账    应收票据与应收款项融资的登记、背书与贴现记录
```

## 五、禁用清单

写完逐项 grep。

### 5.1 句式

| 类别 | 反例 |
|---|---|
| 格言警句 | 外部追问每年都会来 |
| 「不是 A 而是 B」 | 扩产要同时支持四种模式，不是把同一条产线复制一遍 |
| 比喻 | 订单到回款是一条链 |
| 反问设问 | 先看架构撑不撑得住 |
| 祈使与建议 | 先把边界与口径定下来 |
| 抽象主语 | 工程数据的源头放在哪里，决定了…… |
| 对人或团队的评价 | 九个人管一家上市公司的账 |

### 5.2 词汇

撑不撑得住 · 对得起来 · 说不清 · 准不准 · 记得住 · 跟得上 · 划得来 ·
值不值 · 一条链 · 一盘棋 · 一本账 · 全量检查

（另见 `SKILL.md`「文案措辞」的通用禁用词表，以及用户 userPreferences 中的禁用词。）

## 六、交付前自查

在 Phase 8 执行，两项都做完再交付。

1. **只读标题**：把全部页面的 Action Title 单独抽出来列成一列，从上往下通读。
   逐项检查——主语是不是可指认、有没有连续两页同一主语、字数是否超过 24、
   有没有出现数字、腔调是否一致。发现不合格的直接改，**不停下来等用户确认**。

2. **grep 禁用清单**：按 §5.1 与 §5.2 逐项检索。
