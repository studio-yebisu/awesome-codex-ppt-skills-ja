# Curated project examples

Keep showcase cases outside the skill, in the project's examples directory or another user-selected location. Cases contain specific content and design assets. They are optional precedents, never mandatory templates or hidden inputs to a new task.

## Capture the useful material

During image calls, save the exact submitted prompt, the supplied reference images, the returned image, and any exposed model or tool settings. Identify generation and editing separately. Record only metadata the host actually exposes. Never infer an exact model, seed, or timestamp from a filename.

For a selected reconstruction example, retain a compact evidence chain appropriate to the actual work.

- User-approved design image and relevant style reference.
- Exact generation and targeted-edit prompts with matching inputs and outputs.
- Semantic ownership decisions and the distinction between native and raster content.
- A representative OpenCV overlay and its measured scene. Describe only measurement sources that actually contributed.
- Reconstruction contract or constructor scene, required raster assets, editable PPTX, and the corresponding final render.
- A concise case narrative explaining the method, output, and editability boundary.

Select the best intermediate artifacts that explain the method. Conversation transcripts, private user remarks, routine terminal output, caches, and every correction attempt do not belong in the showcase. Leave the original work folder intact unless the user asks to clean it.

## Evidence and presentation

Separate exact records from explanatory material written later. A recovered exact prompt may be presented as such. A remembered summary must be labeled as a summary. Do not invent skipped stages, fresh approvals, source assets, or execution logs to complete a diagram.

Use relative paths for portable copies. If a JSON artifact is relocated, disclose that paths were rewritten while keeping its content decisions unchanged. A small SHA-256 inventory can detect accidental changes. It proves byte integrity against that inventory, not authorship, visual quality, or independent reproducibility.

Check that the PPTX and render being presented still correspond. A later Office save can change the file after its original review. Keep original reviews intact and recheck the current file before describing it as the reviewed deliverable.

Provide a readable overview before technical downloads. Briefly state native versus raster ownership, renderer used, and meaningful limitations. Do not imply fully editable artwork, exact font identification, automatic aesthetic decisions, or successful independent testing without evidence.

Inspect selected assets for private paths, secrets, confidential content, and uncertain redistribution rights before public publication. Local preservation does not authorize publication. Keep configurable profiles and all case images out of the installed skill.
