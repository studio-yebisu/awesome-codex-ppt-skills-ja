# 乔木 bento 演示文稿工作流

## 1. 意图卡

在生成最终 deck 前，先把以下内容写成一页可审阅方案：

- 受众：谁看，已知什么，需要相信或采取什么行动。
- 场景：汇报、路演、发布、教学、演讲、销售或异步阅读。
- 时长：决定主线页数；默认每页 45–90 秒。
- 交付格式：`.bento.html`，以及是否同时保留 `deck.json`。
- 离线边界：图片、字体、短媒体嵌入；外链媒体必须标注联网依赖。
- 证据：来源、数据日期、无法核验的主张。

广义主题默认给三个方向：

- `1a` 叙事型：一个冲突、一条变化、一项结论。
- `2b` 决策型：现状、选项、权衡、建议、下一步。
- `3c` 教学型：概念、机制、示例、练习、总结。

明确推荐一个默认方向。用户说“直接生成”“按默认”“跳过确认”时，
采用默认方向继续；否则停在方案确认，不抢跑制作最终成品。

## 2. source-grounded 资料稿

先生成 `deck-plan.md`，至少包含：

```markdown
# 标题

## 目标与受众
## 一句话结论
## 叙事弧
## 逐页计划
| # | 任务 | 核心信息 | 视觉所有者 | bento 能力 | notes 要点 | 来源 |
## 素材清单
## 风险与 missing evidence
```

“视觉所有者”指一条信息只由一个层级负责：标题、图表、画面、正文或
notes。不要让画面和正文完整显示同一句话。

## 3. 内容到 bento 能力的映射

| 内容 | 首选能力 | 避免 |
|---|---|---|
| 趋势、量级、占比 | chart | 把所有数字写成句子 |
| 规格、价格、功能矩阵 | table | 十几个散落文本框 |
| 同一对象前后变化 | morph + 稳定 id | 每页重新创建不同 id |
| 次级细节、可选解释 | state slide + link | 打断主线增加普通页 |
| 主视觉照片 | image + scrim + ken-burns | 静态满屏图加大段字 |
| 流程、时间线、关系 | path/connector + dash-march 或 morph | 装饰性流程箭头堆叠 |
| 关键数字 | 大字号 + countUp | 小字号 KPI 卡片墙 |
| 视频/音频证据 | media | 用截图假装可播放 |

至少设计一个真正有意义的 motion moment。动效必须解释变化、顺序或
重点，不为“看起来动”而动。

## 4. 视觉默认值

- 画布默认 1280×720；普通内容左右各保留约 96px。
- 标题、结论、正文、注释形成明确字号差，不靠色条和粗边框制造层级。
- 一套主色，最多两套字体；中文正文优先可读性和行距。
- 主视觉优先真实素材或主题背景，前景保持可编辑。
- 不使用左侧彩色竖线 callout、默认网格、施工线、无意义玻璃卡片墙。
- 移动端/小窗口查看时避免过小字和需要精确点击的热区。

## 5. 生成与编辑

新建：

1. 读取官方 bento skill 和最小 schema。
2. 写 `deck.json`，不添加 collab、template、readonly。
3. 用 `bento_deck.py build --new-document` 创建一次 `docId` 并写入新 shell。

编辑：

1. `extract` 原 deck。
2. 记录原 `docId`。
3. 只改文档 JSON，保留未知字段。
4. 用 `--identity-source 原文件.bento.html` 构建为 sibling
   `*.updated.bento.html`；脚本同时复用原 shell。
5. 校验新旧 `docId` 一致。

## 6. 浏览器验收

至少实际检查：

- 封面、信息密度最高的一页、含图表/表格/媒体的一页。
- 编辑器能打开，无密码门、模板实例化或 readonly 意外状态。
- 演示模式可进入、翻页、退出；morph/state/动效行为符合预期。
- 字体、图片、SVG、图表无空白；文本无裁切、重叠和越界。
- speaker notes 存在且不是页面正文的重复。
- 如承诺离线，断网后关键内容仍能显示。

浏览器未实际检查时，必须写 `missing evidence: browser visual review`。
